# Bucketed Imputation Regression: new `bucketimpute` package + out-of-sample evaluation (v1)

The change adds a self-contained R package `bucketimpute` implementing Bucketed Imputation Regression (BIR) per `bucketed-imputation-regression-spec.md`, plus a suite of out-of-sample evaluation scripts and an honest results writeup. BIR buckets the response into equal-frequency quantile bins, fits per-bucket degree-1 `earth` models that reconstruct each predictor from the others, turns standardized reconstruction error into affinity features, and fits a CV-selected lasso of `y` on those affinities; prediction returns a point estimate plus an affinity-weighted heteroscedastic scale. The one mandated deviation from the spec — using `lars` instead of `glmnet` for the lasso — is implemented cleanly and documented in every relevant place. The evaluation is genuinely out-of-sample (disjoint 70/30 splits, fixed seed) and reports BIR's losses to plain `earth` honestly rather than cherry-picking.

Watch for: (1) in-package reproducibility of the lasso penalty depends on the *caller* seeding, because `cv.lars` draws its own random folds and `fit_bir` never sets a seed (likely); (2) the solubility "win" is baseline breakage, not BIR quality, and the results doc says so but the summary table's "Winner: BIR" column reads more favorably than the prose (confirmed); (3) the `se` is only weakly calibrated and near-flat on synthetic_large (confirmed, and disclosed).

**Verdict**: APPROVED

## High-level view

The core algorithm tracks the spec step-for-step: `type=7` quantile cuts with `n+1` breakpoints, `findInterval` bucket assignment, per-bucket per-column degree-1 `earth` reconstruction with `s_{k,j}=sqrt(mean(resid^2))`, the `1/(1+unusualness)` affinity, the lasso, and the affinity-weighted bucket-variance `se`. The stored object carries every field the spec requires plus the lars-specific penalty state. Column names and order are captured at fit time and re-imposed at predict time, so each of the `p` imputation models always predicts the right column from the right others even when `newdata` columns are shuffled.

The lars substitution is the only intended deviation and it is done right: `lars(affinities, y, type="lasso")`, penalty chosen at minimum CV MSE via `cv.lars(..., mode="fraction", plot.it=FALSE)` and `index[which.min(cv)]`, prediction via `predict.lars(..., mode="fraction", type="fit")$fit`. `glmnet` is never imported or called — every mention is documentation explaining the swap. The one gap: `cv.lars` draws its folds from the global RNG and `fit_bir` never seeds it, so the selected penalty is not reproducible without a caller-set seed.

The mandated edge cases are all present: a hard, explicit distinct-buckets error (no silent merge) for tied/near-binary `y`; a two-tier thinness policy (warn below `min_bucket_rows`, error below 2 rows) with a documented `max(p+2,10)` default; and a documented `scale_floor` (1e-8) flooring every residual scale.

The evaluation is strictly held-out and the writeup is candid: BIR loses to degree-2 `earth` on Boston (5.58 vs 3.80) and synthetic_large (1.53 vs 1.06), the solubility "win" is explicitly reframed as robustness to a baseline that extrapolates wildly on wide collinear data, and spam is reported as an expected distinct-buckets error rather than a bug. The known gaps are the caller-dependent lasso reproducibility, the smoke-mode predictor subsetting on solubility, and the weak `se` calibration.

<summary>Issues (5)</summary>

1. **Caller-dependent lasso reproducibility** — `cv.lars` picks folds with the global RNG but `fit_bir` never seeds it, so `lasso_s` (and thus predictions) can vary run to run unless the caller seeds first. Consider seeding internally or documenting that repeatable fits require a caller-set seed.
2. **Solubility "Winner: BIR" overstates the result** — the RMSE table labels BIR the winner while the prose correctly calls it baseline breakage; align the table (e.g. "BIR (robustness only)") so a table-only reader isn't misled.
3. **`se` near-flat on synthetic_large** — the affinity-weighted bucket-variance `se` barely varies when buckets have similar spread (Spearman +0.06); already disclosed, but worth keeping as a known limitation of the uncertainty estimate.
4. **Smoke-mode subsets predictors** — the solubility smoke run uses 20 of 228 predictors and `n=4`; it is a pipeline/cost probe, not a fair wide-data comparison. Documented, but don't let the 1.636-vs-1.630 near-tie be read as the wide-data verdict.
5. **All-zero affinity row `se` guard** — a degenerate row with all-zero affinities is forced to weight 1 to avoid divide-by-zero, silently producing an unweighted `bucket_vars` average for `se`; benign but undocumented.

### Spec fidelity of the training algorithm

`fit_bir` follows the spec's six steps without shortcuts. Cut-points are `quantile(y, probs=seq(0,1,length.out=n+1), type=7)`; assignment is `findInterval(y, cuts, rightmost.closed=TRUE, all.inside=TRUE)`, landing the maximum `y` in bucket `n`. Residual scale is `sqrt(mean(resid^2))` (ordinary residual SE, not MAD), and affinity is exactly `1/(1+sum_j |x_j - pred_j|/s_{k,j})`. The training affinity matrix is built by the same `.bir_affinities` helper used at predict time, so the two phases cannot silently diverge. `bucket_vars[k]` is `var(y[bucket==k])` (0 for single-row buckets). The returned object contains all spec-required fields — `cuts, models, scales, lasso, bucket_vars, n, p, colnames` — plus `lasso_s`, `lasso_mode`, `min_bucket_rows`, `scale_floor`.

### The lars substitution

The one mandated deviation, implemented to the letter:

```r
lasso <- lars::lars(affinities, y, type = "lasso")
cvobj <- lars::cv.lars(affinities, y, type = "lasso", mode = "fraction",
                       plot.it = FALSE)
s_opt <- cvobj$index[which.min(cvobj$cv)]
```

and prediction:

```r
predict(object$lasso, newx = affinities, s = object$lasso_s,
        mode = object$lasso_mode, type = "fit")$fit
```

`s_opt = index[which.min(cv)]` is the correct `lambda.min` analogue — the L1-path fraction at minimum cross-validated MSE. `glmnet` is absent from `Imports` and never called; every mention across DESCRIPTION, roxygen, package doc, and the results md is documentation of why it is *not* used.

Reproducibility caveat: `cv.lars` assigns its CV folds from the global RNG, and `fit_bir` sets no seed, so `lasso_s` — and every downstream prediction — can shift between runs unless the caller seeds first. The eval harness sidesteps this by seeding inside `run_bir`, so the reported numbers are reproducible, but a direct `fit_bir` caller gets no such guarantee. Either seed inside `fit_bir` or document that repeatable penalty selection requires a caller-set seed. (likely)

### Edge-case handling

The distinct-buckets guard is a hard `stop()` when `sort(unique(bucket))` is not exactly `1..n`, naming the tied/near-binary cause and explicitly refusing to merge — the mandated no-silent-merge behavior, confirmed by the spam eval firing at `n>=2` on two-valued `y`. Thinness is two-tier: `stop()` below 2 rows in any bucket, `warning()` below `min_bucket_rows` (documented default `max(p+2,10)`, reflecting each column model regressing on the other `p-1`). Every residual scale is floored via `max(s_kj, scale_floor)` (`1e-8`), preventing divide-by-zero when a bucket fit is intercept-only. (all confirmed)

### Column-name preservation across fit and predict

Named `newdata` is reordered/subset to `object$colnames` at predict time (missing columns error); unnamed `newdata` must match `p` and inherits the training names. Because `.bir_affinities` runs both phases against a matrix already ordered to `cn`, model `(k,j)` reconstructs column `j` from the same others in both. The column-shuffle test (`c("c","a","b")`) that recovers an identical prediction covers this. (confirmed)

### Predictive scale and the all-zero-affinity guard

`se` is `sqrt(sum(w_k * bucket_vars))` with `w_k` the row-normalized affinities. A degenerate all-zero-affinity row would divide by zero, so `row_sums[row_sums==0] <- 1` forces it to an *unweighted* average of `bucket_vars`. Reasonable fallback, but silent and undocumented — a reader inspecting an anomalous `se` would not know the weighting collapsed. Worth a one-line note in the returned-value docs. (confirmed, low severity)

### Tests

The tinytest suite is behavioral, not mocked: it fits a real 150-row synthetic set and asserts on class, presence of every spec-required stored field, prediction shape/finiteness for all three `type`s, affinities in `[0,1]`, `se` non-negativity, default-type equivalence, column-shuffle invariance, the missing-column error, the near-binary distinct-buckets error, `n<2` rejection, and `scale_floor` validation. These would fail on a real regression — a dropped stored field, broken column reordering, or a removed distinct-buckets guard.

Not tested: the `min_bucket_rows` warning path; reproducibility of `lasso_s` across repeated fits (a test here would have surfaced the seeding gap above); and the all-zero-affinity `se` fallback. The reproducibility and warning paths are the most valuable to add.

### Out-of-sample evaluation and honesty

`train_test_split` draws a permutation under `set.seed(2024)` and returns disjoint train/test index sets; models are fit on train and scored on test only. The baseline is a consistent, fair choice (plain degree-2 `earth`) across the regression datasets. The synthetic_large generator matches the mandated spec (seed 2024, n=4000, p=40, the given `y` formula, `x7=x1+N(0,.25)`, `x8=x2+N(0,.25)`, rest noise); `X[,7]`/`X[,8]` are overwritten after `y` is computed from the original `x1..x6`, which is correct.

The verdicts are honest: BIR loses to `earth` on both clean benchmarks (Boston 5.58 vs 3.80; synthetic_large 1.53 vs 1.06 against a noise floor of 1.0), attributed to affinity compression discarding signal and inability to reconstruct the `2.5*x4*x5` interaction. Spam is reported as an expected distinct-buckets error with the verbatim message. The `se` calibration section reports the near-flat synthetic_large result (+0.06) rather than hiding it.

Two places where presentation runs ahead of evidence. The RMSE table's Winner column marks solubility "BIR (see caveat)" while the prose correctly frames it as the naive baselines breaking (earth RMSE ~55, raw-lasso ~293) and BIR being merely bounded/robust — a table-only reader gets a rosier impression than the analysis supports. And the solubility smoke run subsets to 20 predictors with `n=4` for a near-tie (1.636 vs 1.630), a cost/pipeline probe rather than a fair wide-data comparison, sitting in the same table as the full run. Both are disclosed in prose; tightening the table labels removes the only real risk of misreading. (confirmed, low severity)
